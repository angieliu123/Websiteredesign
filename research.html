Research

The evidence behind the behavior layer.

SimCore is the system. SimBench is the benchmark we built to test whether typed, arbitrated user context changes what an agent does. Both are public.

Read the paper on arXiv SimBench on GitHub
SimGuide: Typed Multi-Context User Representations for Preference-Conditioned Agent Planning
Chirag Shah, University of Washington. arXiv:2608.24888
Headline results

Typed blocks with arbitration beat retrieval.

Preference Adherence measures how well a plan satisfies the user's constraints, on a 0–1 scale. The comparison is against retrieval over the same user's past decisions.

The arbitration instruction carries real weight

Removing the arbitration instruction alone costs up to 0.209 Preference Adherence.

Grounding helps where the model has headroom

Grounding each constraint with a worked example of past application adds +0.094 on Llama 3.3 70B, +0.029 on GPT-4o, and +0.002 on Claude Sonnet 4.5, which already scores perfectly on 35 of 47 tasks without it.

Figures are from the paper's abstract across three models and six user-context representations. The paper also reports the benchmark's minimum detectable effect alongside its results.

SimCore

The system under test.

SimCore is the MCP server that implements the behavior layer. It builds and stores Sims, selects the ones that apply to a task, arbitrates conflicts by authority, and logs the decision. SimGuide is the framework evaluated in the paper: typed multi-context representation, explicit conflict arbitration, and optional procedural grounding of individual constraints.

SimBench

How the 47 tasks are constructed.

Existing personalization benchmarks test preference inference inside a single context, so there is nothing to conflict. SimBench is built so that the correct plan depends on which contexts are active.

47

Planning tasks

Preference-conditioned tasks where the plan must respect the user's constraints.

9

Synthetic users

Each represented as a set of typed context blocks.

28

Typed Sims

Potentially conflicting context blocks across those users.

Each task activates a subset of a user's Sims

The same user can need different plans on different tasks, because different contexts are active and their conflicts resolve differently.

Correct plans depend on the active subset

A system that ignores which contexts are active, or that does not arbitrate between them, cannot score well on every task.

Metrics

What we measure.

MetricWhat it measuresHow it is scored
Preference Adherence (PA)Whether the plan satisfies the user's constraints.An LLM judge receives the task, the active Sim definitions, and the agent's plan.
Plan Correctness (PC)Whether the agent picked the right tools.Exact match against tool schemas.
Conflict Resolution Accuracy (CRA)Whether conflicts between Sims were resolved correctly.Correctness of the inter-Sim resolution.

Not to be confused with the unrelated 2025 “SimBench” of group-level human behavior simulation. Ours is the 47-task preference-conditioned planning suite described in the paper above.
