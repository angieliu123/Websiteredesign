Overview

SimCore is an MCP server. Before your agent acts, it makes up to three calls: simcore.select to find the relevant Sims, simcore.arbitrate to resolve conflicts, and simcore.log to record the decision. The result is an instruction set for the agent and a trace ID for your reviewers.

Calls use the standard MCP tools/call method. All payloads are JSON.

Authority tiers. Every Sim belongs to one tier. When rules conflict, a lower number wins: 1 organizational policy, 2 role norm, 3 personal preference.

Sim schema

A Sim is a small, typed, versioned set of rules for one context.

{
  "sim_id": "policy.refunds",
  "version": 4,
  "tier": 1,                       // 1 organizational | 2 role | 3 personal
  "type": "policy",                // policy | role | preference
  "scope": "refunds",
  "owner": "admin",                // who may edit this Sim
  "rules": [
    {
      "rule_id": "refund.inspect_first",
      "text": "No refund before the returned item is received and inspected.",
      "applies_when": ["refund_request", "item_not_returned"]
    }
  ]
}

select

Step 1simcore.select

Returns the Sims relevant to a task for a given subject (a person, role, team, or organization).

Request

{
  "task": "Refund this customer's order",
  "subject_ids": ["org.acme", "role.support_tier_1", "user.8421"],
  "max_sims": 5
}

Response

{
  "selection_id": "sel_30c1",
  "selected": [
    { "sim_id": "policy.refunds", "tier": 1, "version": 4 },
    { "sim_id": "role.support_tier_1", "tier": 2, "version": 2 },
    { "sim_id": "pref.fast_resolution", "tier": 3, "version": 1 }
  ],
  "excluded_count": 21
}

Only the selected Sims go forward. The excluded count is returned so you can monitor selection breadth.

arbitrate

Step 2simcore.arbitrate

Resolves conflicts between the selected Sims by authority tier and returns the instruction set for your agent.

Request

{
  "selection_id": "sel_30c1",
  "task_context": {
    "amount_usd": 780,
    "item_returned": false
  }
}

Response

{
  "winning_authority": "organizational_policy",
  "applied": [
    { "sim_id": "policy.refunds", "rule_id": "refund.inspect_first" },
    { "sim_id": "role.support_tier_1", "rule_id": "refund.over_500_needs_supervisor" }
  ],
  "overridden": [
    { "sim_id": "pref.fast_resolution", "reason": "conflicts with tier 1 rule" }
  ],
  "instruction_set": "Acknowledge the request. Issue a return label, state that the refund follows inspection, and route approval to a supervisor."
}

log

Step 3simcore.log

Writes the resolution trace and returns a trace ID. Store the ID alongside the agent's action.

Request

{
  "selection_id": "sel_30c1",
  "decision": "Inspect item before refund",
  "agent_ref": "support-agent-prod"
}

Response

{
  "trace_id": "rsl_7f2a91",
  "recorded_at": "2026-10-18T17:02:11Z"
}

Worked example

A customer requests an immediate $780 refund. The item has not been returned.

1. Your agent calls select over MCP

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "simcore.select",
    "arguments": {
      "task": "Customer requests an immediate $780 refund. Item has not been returned.",
      "subject_ids": ["org.acme", "role.support_tier_1", "user.8421"]
    }
  }
}

2. It then calls arbitrate with the selection

Using the selection_id from step 1 and the request details. SimCore finds that organizational policy (inspect before refunding) and the role norm (over $500 needs a supervisor) both apply, and that the customer's preference for the fastest resolution is overridden.

3. Your agent acts on the instruction set and logs it

The agent issues a return label, explains the next step, and routes approval to a supervisor. The log call returns rsl_7f2a91.

4. A reviewer reads the trace

trace_id: rsl_7f2a91
task: "Refund this customer's order"
selected_sims: [policy.refunds, role.support_tier_1, pref.fast_resolution]
winning_authority: organizational_policy
decision: "Inspect item before refund"

Errors

CodeMeaningWhat to do
no_matching_simsNothing applies to this task.Proceed with your default behavior, or escalate.
unknown_subjectA subject ID has no Sims.Check the ID, or create the Sims first.
selection_expiredThe selection_id is no longer valid.Call select again.
unresolvable_conflictTwo rules in the same tier conflict.Ask an administrator to resolve it. The trace records the pair.

Sims are created, retrieved, and updated through the same server. Those tools are documented when the sandbox opens. To integrate sooner, become a design partner.
